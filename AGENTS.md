# SeferPresenter Agent Guide

Use this file first when an AI coding agent starts work in this repository.
SeferPresenter is a React/Vite local-first presentation system with presenter,
control, audio editor, audience, multimedia sync, quiz, and sacred-text reading
flows.

Do not inspect the whole repository first. Start with the files below, then read
only the owner files for the task.

## Start Here

- `README.md`: human overview, routes, scripts, backend endpoints, verification.
- `src/App.tsx`: route detection, top-level state, synchronization wiring, command dispatch, mode rendering.
- `src/types/presentation.ts`, `src/types/sync.ts`, `src/types/audio.ts`, `src/types/quiz.ts`: contracts before changing data shape.
- `src/utils/validation.ts`, `src/utils/normalizePresentation.ts`: external/stored data safety.
- `docs/AI_PROJECT_MAP.md`: fast map of entry points and common change paths.
- `docs/COMPONENT_OWNERSHIP.md`: component and state ownership rules.
- `docs/CHANGE_GUIDE.md`: implementation checklists.
- `docs/SYNC_ARCHITECTURE.md`: sync and backend-ready behavior.
- `docs/SYMBOL_INDEX.md`: navigation-critical symbols.
- `docs/ai-navigation.md`: condensed overview kept for quick reading.

## Architecture Rules

- Preserve the refactored folder structure. Do not collapse logic back into `App.tsx`, `MenuPopup.tsx`, or `PresenterScreen.tsx`.
- `App.tsx` may coordinate state and route wiring, but reusable behavior belongs in `src/hooks/`, pure logic in `src/utils/`, contracts in `src/types/`, and UI in the relevant `src/components/*/` folder.
- The local backend is the live source of truth for projected state. Control emits `REMOTE_COMMAND`; supported projection commands are reduced in `server/projection-state-reducer.mjs` through `server/local-server.mjs` and broadcast as `SYNC_STATE`. Presenter displays backend state and may emit real media telemetry, but must not be required for Control-to-Audience navigation.
- Audience mode is read-only for projection controls. Audience quiz answers are separate from presenter demo/correction state.
- Validate and normalize anything loaded from APIs, localStorage, JSON imports, or sync messages.
- Keep media/display telemetry lightweight. Avoid pushing high-frequency or large payloads through full state sync.
- Use neutral wording for public-facing product text; do not add public claims about the private community identity.
- Keep TypeScript/React explicit. Avoid implicit `any` where practical.
- Avoid broad rewrites. Make the smallest change that fits the existing ownership boundaries.
- Distinguish sync-ready presentation state from local UI state. Do not globalize state only to avoid prop passing.

## Documentation Maintenance

If a change affects architecture, ownership, routes, sync, state shape, slide types,
validation, backend endpoints, or navigation-critical symbols, update the relevant
docs in the same change. Do not leave these files stale.

- New/renamed/moved important files or symbols: update `docs/SYMBOL_INDEX.md`.
- Changed folder ownership or component responsibilities: update `docs/COMPONENT_OWNERSHIP.md`.
- Changed sync protocol, remote commands, telemetry, backend endpoints, or localStorage sync behavior: update `docs/SYNC_ARCHITECTURE.md`.
- Changed recommended implementation workflow or verification: update `docs/CHANGE_GUIDE.md`.
- Changed route structure, entry points, or common change paths: update `docs/AI_PROJECT_MAP.md`.
- Changed first-read instructions or agent rules: update this `AGENTS.md`.
- If the public doc index changes, update `README.md`.

## Separation Rules

- Control/menu UI lives under `src/components/control/`.
- Presenter/projector UI lives under `src/components/presenter/`.
- Audience-specific routing/UI lives under `src/components/audience/`.
- Shared UI belongs in `src/components/shared/` and should not know which mode consumes it.
- Stateful behavior belongs in `src/hooks/`.
- Sync protocol and validation live in `src/types/sync.ts`, `src/hooks/useSyncState.ts`, `src/utils/syncProtocol.ts`, and `src/utils/validation.ts`.
- Content/data loading belongs in utilities such as `src/utils/metadataCache.ts`, `src/utils/scriptureLookup.ts`, and server endpoints.

## Do Not Touch Casually

- `public/books/` and `public/metadata.json`: generated by `scripts/generate-verses.js`.
- `node_modules/`, `dist/`: dependencies/build output.
- `legacy/`: local historical record, not product code.
- `presentations.json` and `audio_sync.json`: user/data files. Edit only when the task explicitly targets them.

## Verification

For docs-only changes, checking the diff is usually enough, unless the task
explicitly asks for a build.
For non-trivial code changes, run at least `npm.cmd run build` on Windows. Prefer:

```bash
npm.cmd run test
npx.cmd tsc --noEmit
npm.cmd run lint
npm.cmd run build
```

On non-Windows shells, `npm run test`, `npx tsc --noEmit`, `npm run lint`, and `npm run build` are equivalent.

## Final Response Expectations

Future agents should report:

- Summary of the change.
- Files changed.
- Build/test result, including any skipped checks.
- Risks, uncertainties, or follow-ups.
