# AI Navigation Guide

This guide is for future AI agents modifying SeferPresenter without re-reading the whole repository.
It is intentionally practical: inspect the smallest owner files first, then follow the relevant playbook.

## Mental Model

SeferPresenter is a React/Vite presentation system with four browser routes:

- `/presenter` or `/`: projected screen, source of live state.
- `/control`: operator UI for editing, navigation, media, quiz, and text controls.
- `/audio-editor`: audio cue editor.
- `/audience`: audience-facing read-only projection plus quiz answer UI.

`src/App.tsx` is the central coordinator. It detects the route, owns top-level state, wires hooks, receives commands, emits sync, and chooses which screen to render. It should not become the home for new feature internals.

## Repository Map

- `src/components/presenter/`: projection UI and Sefer reader visuals.
- `src/components/control/`: operator UI, presentation editor, media panels, Sefer controls.
- `src/components/audience/`: audience wrapper and audience quiz UI routing.
- `src/components/quiz/`: quiz presenter/controller/audience views and quiz controls.
- `src/components/shared/`: reusable UI widgets.
- `src/hooks/`: stateful behavior: sync, media playback, keyboard, Sefer reader, scripture navigation, quiz timers/answers/audio.
- `src/utils/`: pure or mostly-pure helpers: validation, normalization, sync protocol, scripture parsing/lookup, quiz parsing/scoring, media parsing.
- `src/types/`: shared contracts. Update these before updating implementations.
- `server/`: local backend, static serving, SSE, API persistence, auth gate.
- `scripts/`: generation and utility scripts.
- `__tests__/`: Vitest coverage for utils/hooks.
- `public/`: static assets, PWA files, generated book data.

## State Categories

Persistent content:

- Presentations: `Presentation` and `Slide` in `src/types/presentation.ts`, saved through `/api/presentations` into `presentations.json`.
- Audio sync maps: `AudioSyncMap` in `src/types/audio.ts`, saved through `/api/audio-sync` into `audio_sync.json`.
- Generated sacred text data: `public/books/*.tsv` and `public/metadata.json`, generated by `scripts/generate-verses.js`.

Local/browser state:

- Stored presenter state and background lock in `localStorage`, loaded/normalized by `src/utils/normalizePresentation.ts` and persisted by `src/hooks/useSyncState.ts`.
- Audience answer/session state in `src/hooks/useQuizAnswers.ts`.

Live synchronized state:

- Full state: `SYNC_STATE` in `src/types/sync.ts`.
- Remote commands: `REMOTE_COMMAND` in `src/types/sync.ts`.
- Lightweight media/display updates: `AUDIO_TELEMETRY`, `VIDEO_TELEMETRY`, `DISPLAY_TELEMETRY`.
- Quiz answer events: `/api/quiz-answer` and `/api/quiz-events` in `server/local-server.mjs`.

Derived UI state:

- Active background: `src/hooks/useBackgroundResolver.ts`.
- Active scripture state: `src/hooks/useScriptureNavigation.ts`.
- Quiz subslides/timer/score helpers: `src/utils/quizUtils.ts`, `src/hooks/useQuizTimer.ts`.

## Sync Flow

1. Control actions call props from `MenuPopup`.
2. In `/control`, most props emit `REMOTE_COMMAND` through `useSyncState.emitCommand`.
3. Presenter receives commands in `App.handleRemoteCommand`.
4. Presenter mutates local state and emits `SYNC_STATE` or specific telemetry.
5. Other tabs/devices apply state through `useSyncState`.
6. The local server mirrors sync over SSE/API for LAN/mobile use.

When adding a synchronized action, update in this order:

1. Add/extend types in `src/types/sync.ts`.
2. Validate the message in `src/utils/validation.ts`.
3. Emit from control props in `src/App.tsx`.
4. Handle in `App.handleRemoteCommand`.
5. Broadcast state or telemetry through `useSyncState`.
6. Check presenter, control, and audience behavior.

## Ownership Rules

- `src/App.tsx`: orchestration only. Add route-level wiring, state refs, and command dispatch here when necessary.
- `src/hooks/useSyncState.ts`: broadcast/SSE state application and persistence. Keep protocol handling centralized here.
- `src/hooks/useScriptureNavigation.ts`: transitions between slides, scripture mode, and manual Sefer navigation.
- `src/hooks/useSeferReader.ts`: book/chapter/verse reader state and metadata/book TSV loading.
- `src/components/control/MenuPopup.tsx`: control layout coordinator. Prefer moving new subpanels into smaller files under `src/components/control/`.
- `src/components/presenter/PresenterScreen.tsx`: projection rendering for text/image/video/quiz. Avoid adding controller logic here.
- `src/components/audience/AudienceScreen.tsx`: read-only projection choice and audience quiz entry. Do not add presenter controls here.
- `src/utils/*`: pure logic that can be tested without React.

## Common Change Playbooks

### Add or change quiz behavior

Inspect first:

- `src/types/presentation.ts`
- `src/types/quiz.ts`
- `src/utils/quizUtils.ts`
- `src/hooks/useQuizTimer.ts`
- `src/hooks/useQuizAnswers.ts`
- `src/components/quiz/*`
- Quiz sections in `src/App.tsx` and `src/components/control/MenuPopup.tsx`

Rules:

- Persistent quiz content lives in `Slide.quizData`.
- Runtime quiz state lives in `QuizSyncState` and hooks, not in `presentations.json`.
- Presenter demo selection is separate from audience answers.
- Timer remaining time is derived from timestamps; do not broadcast per-second countdown state.
- Update `__tests__/quiz/quizUtils.test.ts` when parser/scoring/subslide behavior changes.

### Add or change synchronization

Inspect first:

- `src/types/sync.ts`
- `src/utils/syncProtocol.ts`
- `src/utils/validation.ts`
- `src/hooks/useSyncState.ts`
- `server/local-server.mjs`
- `src/App.tsx`

Rules:

- Prefer a typed `REMOTE_COMMAND` for operator intent.
- Prefer telemetry messages for frequent media/display updates.
- Keep server command handling stateless unless the endpoint intentionally mutates `currentState`.
- Validate incoming messages before applying them.

### Change presenter UI

Inspect first:

- `src/components/presenter/PresenterScreen.tsx`
- `src/components/presenter/SeferReaderScreen.tsx`
- `src/components/presenter/SeferFlowView.tsx`
- `src/components/presenter/VerseSidebar.tsx`
- `src/components/shared/AutoResizeText.tsx`
- `src/components/shared/SlideVisualizer.tsx`

Rules:

- Presenter should render from props and report media telemetry; it should not own app navigation.
- Text must remain responsive and non-overlapping.
- Video slide behavior must keep controller/projection telemetry symmetry.

### Change control UI

Inspect first:

- `src/components/control/MenuPopup.tsx`
- `src/components/control/PresentationEditor.tsx`
- `src/components/control/SlideRow.tsx`
- `src/components/control/PresentationList.tsx`
- `src/components/control/BackgroundSelector.tsx`
- `src/components/control/AudioPanel.tsx`
- `src/components/control/VideoControls.tsx`
- `src/components/control/SeferControlPanel.tsx`

Rules:

- Keep `MenuPopup` as a coordinator. Put new controls in focused child components.
- Preserve desktop operation, but avoid layout choices that block future mobile/tablet control.
- When a control changes presenter state, route the action through the command/sync path.

### Change sacred text or Sefer navigation

Inspect first:

- `src/hooks/useSeferReader.ts`
- `src/hooks/useScriptureNavigation.ts`
- `src/hooks/scriptureNumerals.ts`
- `src/utils/scriptureLookup.ts`
- `src/utils/scriptureParser.ts`
- `src/utils/metadataCache.ts`
- `src/utils/hebrewText.ts`
- `src/components/control/SeferControlPanel.tsx`
- `src/components/presenter/SeferReaderScreen.tsx`

Rules:

- Do not edit generated `public/books/*.tsv` or `public/metadata.json` by hand.
- Preserve range semantics: `verseStart`, active `verse`, optional `verseEnd`.
- Use `scriptureKind` to distinguish `sefer` and `tanaj` behavior.
- Keep navigation commands (`navigate`, `next`, `previous`) explicit with `commandId`.
- Update scripture lookup/parser tests when parsing or lookup changes.

### Change validation or import/export

Inspect first:

- `src/utils/validation.ts`
- `src/utils/normalizePresentation.ts`
- `src/components/control/ImportExportPanel.tsx`
- `src/components/control/PresentationEditor.tsx`
- `server/local-server.mjs`

Rules:

- Treat API, imports, localStorage, and sync as untrusted.
- Keep validation errors actionable and in Spanish where shown to users.
- Normalize public asset paths through `normalizePublicPath`.

### Change backend/local-first behavior

Inspect first:

- `server/local-server.mjs`
- `server/dev.mjs`
- `vite.config.ts`
- `README.md`
- `src/hooks/useSyncState.ts`

Rules:

- Preserve local-first operation.
- Keep `/api` endpoint compatibility unless the task explicitly changes it.
- If adding protected mutation routes, include auth behavior when `SEFER_REQUIRE_AUTH=true`.
- Keep audience/PWA endpoints light.

## Testing Targets

- Pure presentation/validation changes: `npm.cmd run test`.
- Type or contract changes: `npx.cmd tsc --noEmit`.
- UI changes: run `npm.cmd run dev`, inspect `/presenter`, `/control`, and `/audience`.
- Sync/media changes: use two browser windows or devices; verify control commands, presenter state, and audience read-only behavior.
- Build-risk changes: `npm.cmd run build`.

## Anti-Patterns

- Adding feature logic directly to large components when a hook, util, or child component owns it better.
- Duplicating scripture parsing, quiz scoring, or path normalization.
- Mutating presentation objects in place.
- Treating audience answers as presenter/control state.
- Broadcasting high-frequency timer ticks or media progress through full `SYNC_STATE`.
- Editing generated book data manually.
- Adding public-facing community identity language instead of neutral product wording.
